## Project Overview

Docusaurus v3 documentation + marketing site for KnowFlow. TypeScript with React 19. Primary content is Chinese (zh-Hans); English (`en`) is a real locale with translated marketing pages.

KnowFlow has **two product lines**, and the site is organised around that split:

| Product line | Marketing page | Docs | Source of truth |
|---|---|---|---|
| 企业知识库 (Knowledge Base) | `/product` | `/docs` (from `docs/`) | `zhishi/ragflow` |
| 智能问数 (Analytics) | `/analytics` | `/analytics/docs` (from `analytics-docs/`) | `zhishi/ragflow/knowflow-analytics` |

## Development Commands

```bash
npm install          # Install dependencies (use npm, not yarn)
npm start            # Dev server with hot reload
npm run build        # Production build (builds BOTH locales)
npm run serve        # Serve production build locally
npm run clear        # Clear Docusaurus cache
npm run typecheck    # TypeScript type checking via tsc
npm run deploy:aliyun  # Build + deploy to Aliyun, then baidu-push and seo-check
npm run write-translations -- --locale en   # Re-scaffold i18n JSON after nav/footer changes
bash scripts/seo-check.sh [baseUrl]         # Status-code audit of legacy/live URLs
```

No linting or test framework is configured.

:::caution `npm run serve`
`docusaurus serve` mis-resolves path segments containing dots (e.g. `/docs/博客/knowflow-v2.1.6-image-search`) and returns 404 for files that exist. That is a local-only quirk — Nginx `try_files` resolves them. Use `scripts/seo-check.sh` against the real deployment to judge routing.
:::

## Deployment

1. **GitHub Pages** — automated via `.github/workflows/deploy.yml` on push to `main`.
2. **Aliyun** — manual via `npm run deploy:aliyun` (`deploy.sh`), rsync/scp to `139.224.59.152:/www/wwwroot/www.knowflowchat.cn`.

`deploy.sh` mirrors every `x.html` into `x/index.html` so the site works under any Nginx `try_files` variant. Server-side rules (301s for the old blog URLs, 410s for retired pages, domain/protocol canonicalisation) live in `nginx/knowflowchat.conf` and must be applied on the server manually.

Production URL: `https://www.knowflowchat.cn` (`static/CNAME`).

## Architecture

### Content

- `docs/` — 企业知识库 docs, Chinese, autogenerated sidebar; folder ordering via `_category_.json`
- `analytics-docs/` — 智能问数 docs, separate docs plugin instance (`id: 'analytics'`)
- `blog/` — the **only** blog. Posts previously lived under `docs/博客/`; they were moved here and the old URLs are redirected. Never put blog posts back under `docs/`.

### Custom pages (`src/pages/`)

`index.tsx`, `product.tsx`, `analytics.tsx`, `about.tsx`, `contact.tsx` plus the Markdown legal pages `privacy.md` and `terms.md`.

Marketing pages hold **no inline copy**. Text lives in `src/content/*` as per-locale dictionaries and is read through `useLocaleContent`:

```tsx
const content = useLocaleContent(homeContent);   // src/content/home.ts
```

Adding a language means adding a key to those dictionaries — the components stay untouched. `analytics.tsx` deliberately reuses `product.module.css` for the shared marketing shell.

### SEO (`src/seo/` + `plugins/seo/`)

- `src/seo/routes.ts` — one reviewable list of what is not indexed and which legacy URLs redirect
- `src/seo/structuredData.ts` — site-level schema.org JSON-LD
- `plugins/seo/index.js` — a `postBuild` plugin that injects `noindex` into thin/untranslated routes and writes redirect stubs for legacy URLs

Rules that matter:

- **Never add a blog post URL under `/docs`.** SEO value is in `/blog`.
- Blog tag/author/pagination pages are intentionally `noindex, follow` and excluded from the sitemap; they were previously reported as soft 404s.
- English docs and blog are `noindex` because they are still Chinese content. **Remove the corresponding entry from `LOCALE_NOINDEX_ROUTES` as each section gets translated.**
- Retired pages must 404/410, never redirect to the homepage (Google treats that as a soft 404).

### i18n

- `i18n/en/code.json`, `docusaurus-theme-classic/*.json`, `docusaurus-plugin-content-docs*/current.json` — navbar, footer and sidebar category labels
- `i18n/en/docusaurus-plugin-content-pages/` — English overrides for the Markdown pages (`privacy.md`, `terms.md`)
- After changing navbar/footer labels, re-run `write-translations` and fill in the new keys.

### Styling

- `src/css/custom.css` — Infima variables, navbar, the docs product switcher (`.productSwitcher*`) and legal-page layout
- Page-scoped CSS Modules alongside each page

### Product switcher

`src/sidebar/productSwitcher.ts` emits a sidebar `type: 'html'` item injected at the top of both docs sidebars (`sidebars.ts`, `sidebars-analytics.ts`). It reads `process.env.DOCUSAURUS_CURRENT_LOCALE` to build locale-prefixed links. No theme swizzling is involved — keep it that way.

## Key Patterns

- `onBrokenLinks: 'throw'` — builds fail on dead links. Same-page hash links must use a native `<a>`, not `<Link>` (Docusaurus only knows anchors generated from Markdown headings).
- MDX parses `.md` too: `<http://example.com>` autolinks break the build. Write `[url](url)`.
- Legal pages carry `【placeholder】` markers for the legal entity, address and contact email. **They must be filled before the pages are treated as published.**
- `tsconfig.json` excludes `KnowFlowPro/` and `my-wiki/` — unrelated projects that share the repo.
