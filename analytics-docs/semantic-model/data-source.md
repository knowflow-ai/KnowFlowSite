# 数据源接入

数据源是一等实体，可以按项目绑定，**一个项目里可以同时接多个库**。

## 支持的数据源

| 类型 | 说明 |
|---|---|
| PostgreSQL | 主要支持方言，全部功能均在真库上验证 |
| MySQL | 五种时间粒度、同比自连接与占比窗口均与 PostgreSQL 逐行比对一致 |
| 上传表格 | Excel 落库成数据源，支持一次导入多张工作表、追加或替换、删除 |

其它方言尚未支持。

## 连接业务库

在「数据库连接」中添加连接串：

```text
postgresql://user:password@host:5432/your_database
mysql://user:password@host:3306/your_database
```

容器访问宿主机数据库时使用 `host.docker.internal` 代替 `localhost`。

:::warning
- 请使用专用**只读**数据库账号。
- 数据源不能是服务自己的 catalog 库，否则内部表会被当业务表建模。
- 连接串密码必须 URL-safe。
:::

## 选择进入语义层的表

连接成功后，系统读取 Schema 并列出全部表。**只勾选真正需要进入语义层的表**——业务数据仍留在原数据库中，系统维护的是经过治理的目录、版本和查询规则。

![选择需要进入语义模型的业务数据表](/img/analytics/product-data-source.png)

建议的取舍：

- ✅ 事实表（订单、交易、事件明细）与维度表（客户、商品、门店、日期）
- ❌ 日志表、临时表、中间表、系统表
- ❌ 既无主标识也无业务度量的表（不会成为事实根，进来只增加噪声）

## Schema 快照与漂移检测

导入时系统会保存一份 Schema 快照。当上游数据库新增字段、改名或删表时，系统会标记**漂移**，提示哪些语义对象受影响，避免线上查询范围被无意改变。

:::tip 大型 Schema
AI 建模在请求周期内同步执行。表特别多时建议**分批导入**，或调高服务超时。
:::

## 上传表格

不连数据库也可以开始。上传 Excel 后系统会把它落库成一个数据源，走与数据库表完全相同的建模与问数链路：

- 一次导入多张工作表
- 支持追加或替换已有表
- 支持删除

适合快速验证效果，或分析没有进入数据仓库的线下数据。
