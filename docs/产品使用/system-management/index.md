# 系统管理

KnowFlow 系统管理用于集中维护平台账号、组织关系、协作组、文件、知识库和用户模型配置。管理员登录后台后，可以在左侧导航进入各个管理模块。

> 产品截图预留：系统管理左侧导航总览。

## 访问入口

访问后台管理地址：

```text
http://主机 IP/admin
```

默认管理员账号：

```text
账号：admin@gmail.com
密码：admin
```

登录后进入系统管理后台。后台登录态与前台 KnowFlow 使用态隔离，退出后台不会影响前台登录。

## 导航模块

| 模块 | 作用 | 常见操作 |
| --- | --- | --- |
| 服务状态 | 查看系统服务运行情况 | 检查服务版本和运行状态 |
| 用户管理 | 维护平台用户 | 新建用户、编辑用户名、重置密码、删除用户 |
| 组织架构 | 维护企业纵向组织树 | 新建组织、创建子组织、设置组织管理员、管理成员 |
| 协作组管理 | 维护横向协作成员组 | 新建协作组、添加成员、移除成员 |
| 文件管理 | 管理后台文件资源 | 上传文件、下载文件、删除文件 |
| 知识库管理 | 统一管理知识库资源 | 新建知识库、导入导出、管理文档、管理权限 |
| 用户配置 | 管理用户模型配置 | 查看默认模型、调整用户对话模型和嵌入模型 |

企业版本还可能显示注册白名单、角色管理、系统监控等扩展模块。

## 管理对象关系

系统管理中的几个核心对象关系如下：

```text
用户
├── 归属一个主组织
├── 可加入多个组织
├── 可加入多个协作组
└── 可被直接授予知识库权限

组织
├── 支持上下级层级
├── 可设置组织管理员
└── 对知识库授权时作用于当前组织及下级组织成员

协作组
├── 归属一个组织范围
├── 不参与组织树层级
└── 适合跨部门项目或临时专项协作

知识库
├── 可管理文档
├── 可导入导出
└── 可分别授权给用户、组织、协作组
```

## 权限边界

- 超级管理员可以管理全局用户、组织、协作组、文件、知识库和用户配置。
- 组织管理员用于管理其所在组织及下级组织范围内的成员和资源。
- 知识库权限通过用户、组织、协作组三类主体授予，权限等级包括查看者、编辑者、管理员。
- 同一用户从多个来源获得知识库权限时，系统以最高有效权限为准。

更完整的权限规则请参考 [RBAC 权限管理](/docs/产品使用/rbac-permission)。

## 推荐配置流程

1. 在**组织架构**中创建企业部门层级。
2. 在**用户管理**中新建用户，并选择用户主组织。
3. 在**组织架构**中补充成员关系，按需设置组织管理员。
4. 在**协作组管理**中创建跨部门项目组。
5. 在**知识库管理**中创建知识库，并按用户、组织或协作组授权。
6. 在**用户配置**中检查用户对话模型和嵌入模型是否正确。
